The Document Object Model (DOM)

DOM 是 Document Object Model (文档对象模型) 的缩写，它是==一种用于表示和操作HTML、XML 或SVG 文档的标准编程接口==。简单来说，DOM 是一种将网页内容以对象形式存储的方式，并提供了一系列方法，让JavaScript 等脚本语言可以访问和修改网页内容、结构和样式

**DOM** stands for **Document Object Model**. It is a standard programming interface used to represent and manipulate HTML, XML, or SVG documents. Simply put, the DOM is a way to store the content of a web page as objects, and it provides a set of methods that allow scripting languages like JavaScript to access and modify the content, structure, and styles of the web page.





It defines:
• The HTML elements as objects
• The properties of all HTML elements
• The methods to access all HTML elements
• The events for all HTML elements

## 1.2 Offline web apps

Traditional Web applications simply do not work without a network.
Intermittent network availability especially an issue for mobile Web applications.

Main idea: Work offline with a locally deployed application on a local database, and synchronize when going online again

Offline storage is about capturing specific data generated by the user, or resources that the user has expressed an interest in.

Older offline storage techniques include
• Cookies
	• Extremely limited data capacities (4KB each/20 cookies)
	• Transfer inside HTTP header: slows down network activity
• Plugin-based storage (all discontinued)
	• Flash, Java applets, Google Gears, Microsoft Silverlight
	• Problem: You have to assume the plugin is present (and in the right version). It's not uncommon for company firewalls to block plugins and for plugin releases to lag behind, or not exist at all on certain OS.

Web Storage
- Key-value store
	- Values can be of any type (acc. to spec)
- localStorage: 
	- Data resides in the user’s browser, on a per-browser basis Data can be retrieved later on, even when the browser has been closed and re-opened
- sessionStorage:
	- Same as above, but data is removed when the window is closed

是一种在浏览器端保存数据的机制，主要有两种类型：`localStorage` 和 `sessionStorage`。

 Key-value store（键值对存储）
- 是一种简单的存储方式，用键（key）和对应的值（value）来保存数据。
- **按规范**，值理论上可以是任意类型，但**在实际中必须是字符串**，如果是对象，需要先转换成字符串（例如用 JSON）。

 localStorage（本地存储）
- 数据保存在用户的**浏览器中**，针对每个浏览器（不同浏览器之间不共享）。
- 即使关闭浏览器，数据也**不会丢失**，下次重新打开网页时仍然可以访问。
- 常用于保存登录信息、主题偏好等需要长期保留的数据。

 sessionStorage（会话存储）
- 和 `localStorage` 类似，也是存储在浏览器中的键值对。
- **区别是：**数据在**当前窗口/标签页关闭时就被清除**。
- 适用于临时数据，例如某次会话中的表单内容。

什么是 **Interpretive Language（解释型语言）**？
- 指：**代码在运行时逐行被解释执行**，而不是预先编译成机器码。
- 特点：
    - 不需要编译（或只需要轻量编译）
    - 通常由**解释器**（interpreter）运行
    - 运行效率通常比编译型语言低，但更灵活


---


**Interpretive Language（解释型语言）** 的对立面是：

> ✅ **Compiled Language（编译型语言）**


| 概念       | 解释型语言（Interpretive Language） | 编译型语言（Compiled Language） |
| -------- | ---------------------------- | ------------------------ |
| 执行方式     | **逐行解释执行**                   | **一次性编译成机器码再运行**         |
| 是否需要编译   | ❌ 不需要（或轻量字节码编译）              | ✅ 必须预编译                  |
| 运行效率     | 通常较慢                         | 通常更快（直接运行机器码）            |
| 可移植性     | 跨平台性好（只要有解释器）                | 依赖编译目标平台                 |
| 示例语言     | Python, JavaScript, Ruby     | C, C++, Go, Rust, Swift  |
| 常见错误出现时机 | 运行时（Run-time）                | 编译时（Compile-time）        |
- **解释型语言**：靠“解释器”逐行读代码并执行（如 Python）
    
- **编译型语言**：靠“编译器”先把代码**全部变成机器码**，再运行（如 C）


**解释型语言是边读边跑；编译型语言是先翻译好再跑。**


---

**Scripting Language（脚本语言）**？
- 指：**专门用于控制其他程序（如操作系统、浏览器、游戏引擎等）行为的语言**。
- 脚本语言本质上也是**解释执行的语言**，但它更强调“用途”而不是“执行方式”。
    
- 特点：
    - 用于**自动化任务**，而不是写大型程序
    - 轻量、小型、快速开发
    - 经常用于 **网页交互、服务器配置、系统运维脚本** 等场景



---


“Scripting Language（脚本语言）”的对立面通常是指：

> **System Programming Language（系统编程语言）** 或 **Compiled Application Language（编译型应用语言）**


| 特性    | 脚本语言（Scripting Language）   | 系统编程语言 / 编译型语言          |
| ----- | -------------------------- | ----------------------- |
| 主要用途  | 控制、自动化、快速编写脚本，通常操作其他程序或环境  | 开发操作系统、驱动程序、底层软件、大型应用程序 |
| 执行方式  | 通常解释执行，快速开发                | 通常编译成机器码，执行效率高          |
| 语言示例  | Bash、Python、JavaScript、Lua | C、C++、Rust、Go           |
| 运行效率  | 较低，偏重灵活性和易用性               | 高，偏重性能和硬件控制             |
| 开发复杂度 | 简单，适合写短小的任务脚本              | 复杂，需要考虑内存管理、硬件细节等       |


- **脚本语言**：更偏向**自动化和控制**，常用于“写脚本”快速完成任务
    
- **系统编程语言**：更偏向**底层开发和性能要求高的应用**，编译执行，功能复杂

## 2.2 Dynamic web pages

There are currently two options for making web pages dynamic and interactive:

plugins:
• A frame containg a plugin execution environment is embedded in the website; inside the frame arbitrarily complex dynamic content can be executed.
• Popular for gaming (“Flash games“), video streaming (YouTube pre-HTML 5), etc.
• Examples (all deprecated): Java Applets, Adobe Flash, Microsoft Silverlight, Google Gears, …
• Deprecated because (i) plugin might not be present or in the wrong version, (ii) only small part of the website is dynamic, (iii) security problems

JavaScript:
• JavaScript code can be embedded in HTML files directly
• Manipulates the DOM tree to make entire page dynamic
• Standard approach today


JavaScript is an object-oriented scripting (=interpreted) language most often used for client-side Web development
• It is a dynamic, weakly typed, language with first-class functions and prototype-based realization of objects
• JavaScript was influenced by many languages and was designed to syntactically look like Java
• JavaScript, despite the name, is essentially unrelated to the Java programming language


## 2.3 Characteristics of JavaScript 
Variables are weakly typed
• No explicit declaration of types, e.g., Integer, String or Boolean, for a variable
• Types are associated with values, not variables
• It is valid to assign values of different types to the same variable


Code is dynamically interpreted
• At runtime, code is stored as text and interpreted into machine instructions as the program runs
• No precompiling as for example in Java, C, C# and others
• Current browsers use specific JavaScript interpreters
	• Their speed is often used as unique selling point
	• Examples: Chrome uses V8, Firefox uses SpiderMonkey, WebKit (Safari) uses JavaScriptCore, Edge uses Chakra

Objects are prototype-based
• Creation of new instance by referencing existing objects, including all their attributes
• The attribute prototype stores the reference of an instance to its prototype


Objects are prototype-based (continued)
• Changes to the attributes of a prototype during runtime also affect the instance, e.g.:
• In contrast, a Java, C++ or C# object has a defined type, with superclasses and virtual superclasses or interfaces strictly defining its functionality
• Prototypes can be used to emulate Java-style types in JavaScript, but the similarity is only skin deep


JavaScript functions are first-class objects
• JS functions are a special type of object, with all characteristics of an object
![[400_Anwendungssystem/image/Pasted image 20250701132734.png]]

• JavaScript functions can be attached to objects so that they behave like methods, but
they can also be invoked in other contexts and/or reattached to other objects at runtime
• In contrast, a Java object's methods are tied to the object that owns them and can be
invoked only via that object

🔍 调试困难（Debugging）
由于 JavaScript 通常同时处理客户端和服务器端逻辑（特别是在全栈开发中，如使用 Node.js），调试变得更加复杂。

弱类型语言（weak typing）特性使得在设计阶段很难发现类型错误，很多错误只能在运行时才暴露出来。

🔐 安全性问题（Security）
JavaScript 代码在浏览器中是以明文形式公开的，意味着任何人都可以查看和分析源码，增加了被攻击或被篡改的风险。

🐢 性能问题（Performance）
如果客户端逻辑复杂，JavaScript 代码量大，会导致所谓的“fat client”（胖客户端）。

在资源有限的设备（如手机或旧设备）上，运行这些复杂的逻辑可能会降低页面加载速度和用户体验。

🌐 浏览器兼容性问题（Cross-Browser Incompatibilities）
不同浏览器对 JavaScript 的支持程度不同，特别是旧版浏览器，可能缺乏对某些功能的支持。

开发者常常需要进行额外测试，甚至编写多个版本的代码来保证兼容性。

## 3.4 Pros and cons of using AJAX

Advantages

Seamless HTML integration
AJAX is not something embedded within HTML
No separate markup language interwoven with HTML

Standards-based cross-browser support
AJAX works with nearly every browser
No plug-ins required for AJAX

Backend agnostic
AJAX works with every HTTP-compliant
backend, e.g. Java (EE/SE), PHP, ASP, .NET,….


Distribution
Other RIA technologies (Adobe Flash, Microsoft Silverlight,…) require special backends, HTML or browser plug-ins


---

Disadvantages

Usability
Breaking the “back” button: Browsers cache static page only
- 当页面是通过 AJAX 局部更新的，而不是重新加载整个页面时，**浏览器不会自动记录这些状态变化**。
    
- 所以用户点击“返回”按钮时，页面不会回到上一个 AJAX 状态，而是回退到上一个完整页面。
    
- HTML5 的 `history.pushState()` 和 `popstate` API 后来提供了解决方案，使得 AJAX 页面也能更新地址栏并支持“后退”。


addressed in HTML 5 Bookmarking is difficult because the client controls state and generates page, not the server
- 传统网页每个页面都是由服务器生成，有固定的 URL，可以直接添加书签或分享。
- AJAX 应用中，页面内容是由 JavaScript 动态生成的（客户端控制状态），同一个 URL 对应的内容可能不固定。
- 这样用户无法方便地**添加书签、刷新或分享特定状态的页面**。
- 可通过 URL 哈希（如 `#tab=3`）或 HTML5 的 `pushState()` 技术来绕过这个限制。




Performance
Number of server calls may increase Many fine-grained asynchronous calls instead of few coarse-grained calls
- AJAX 允许发起很多小请求（例如每次用户点击或输入就发一次请求）。
- 相比之下，传统服务器页面可能只发一两个大请求。    
- 缺点是：**请求频繁，容易增加服务器负载，影响性能**，尤其是在网络延迟高的情况下。


Security
Cross-origin resource sharing (CORS) prohibited (e.g., you cannot load data from http://www.x.com from a client that is hosted on http://www.y.com - addressed by XMLHttpRequest 2.0)

- 默认情况下，**浏览器不允许 AJAX 请求访问不同源（域名、端口或协议不同）的服务器数据**。

假设你的网站托管在 `https://client.com`，API 服务器在 `https://api.server.com`，浏览器默认禁止 `client.com` 通过 AJAX 访问 `api.server.com` 的数据。
如果 `api.server.com` 的响应头包含：
`Access-Control-Allow-Origin: https://client.com`
浏览器就允许这个跨域请求成功，前端 JavaScript 可以正常获取数据。

浏览器运行在用户的电脑或设备上，也就是客户端（Client）。具体来说：
- **浏览器是客户端应用程序，运行在用户的操作系统上（如 Windows、macOS、Linux、iOS、Android）**
- 当用户访问你的网站 `https://client.com` 时，浏览器加载并执行你网站的代码（HTML、JavaScript 等）
- 你的 JavaScript 代码在浏览器里运行，试图通过 AJAX 向 `https://api.server.com` 发送请求

响应头（Response Header）**？

- **响应头** 是服务器在回应浏览器（或客户端）请求时，随同数据一起发送的**一组元信息**（metadata）。
    
- 它们告诉浏览器关于返回内容的类型、长度、缓存策略、跨域策略、安全性等各种信息。

Web Assembly (Wasm)

WebAssembly is a portable format for executable programs. All modern browsers have support for it, and it can be significantly faster than JavaScript as it does not have to be interpreted.

Developers usually write their software in another language (e.g., TypeScript, Kotlin, Rust), which is then compiled to WebAssembly.

Single Page Applications

A single page application is a web application that does not direct users to new websites, but rewrites the current DOM dynamically. SPAs heavily use JavaScript, CSS, and new HTML features. This allows developers to recreate desktop-like applications on the web


----


Progressive Web Apps are a special type of website that adheres to additional standards.

Some browsers (e.g., Chromium-based Browsers, Safari, Firefox Android) can then “install” these applications, so that they also work without an Internet connection and behave similar to native apps.

Developers only need to write their application once and can deliver a native-feeling experience on multiple platforms

Electron

Electron is an open-source software framework to create desktop applications using web technologies.

The SpaceX Crew Dragon Touchscreen Interface is completely based on a similar technology.

Die Unified Modeling Language (UML) ist eine visuelle Sprache zur Spezifikation, Konstruktion und Dokumentation technischer Systeme
• Erste Ansätze Mitte der 90er von Grady Booch, James Rumbaugh und Ivar Jacobson (Rational Software Corporation)
• Ziel: „Unified Method“ verschiedener objektorientierter Modellierungsmethoden
• als einheitliche Modellierungssprache seit 1997 von der OMG (Object Management Group) standardisiert
• Aktuelle Version (seit Juni 2015): UML 2.5
• Spezifikation: http://www.omg.org/spec/UML/

# 3 UML Spezifikation

UML Infrastructure
• Definiert den Sprachkern der UML (z.B. Konzepte wie Klasse, Assoziation, Attribut und Methode)
• Erweiterbar durch Erweiterungsmechanismen auf Nutzer:innen-Ebene und Profile

UML Superstructure
• Erweitert den Sprachkern auf den vollständigen UML-Sprachumfang
• Definiert Modellelemente, Notationen, Diagrammtypen
• Definiert welche Eigenschaften Sprachelemente haben dürfen und welche Beziehungen zulässig sind

UML Object Constraint Language (OCL)
• Zur Spezifikation von Invarianten und Bedingungen
• Metamodell-basierte Definition
• Konsistent zum UML-Metamodell

## 6.1 Associations and navigability

### 6.1.1 bidirectional association

Associations are therefore the basis for constructing your own complex data types. The navigability of the association has so far been unspecified in the model. In the code, it has simply been assumed that navigability should be possible in both directions, i.e., that a bidirectional association exists.

![[MODEL-DRIVEN SOFTWARE ENGINEERING/Chapter_06_07_UML_OCL/01_01_UML/image/Pasted image 20250408213730.png]]

}

class Department {

### 6.1.3 types of associations

Basically, the following types of associations can be distinguished with regard to their cardinality:
- **1:1 relationship** : Each object of type K1 is assigned a maximum of one object of type K2 , and vice versa. Example: "Man is married to woman."
- **1:N relationship** : Each object of type K 1 can be assigned any number of objects of type K 2 , but for each object of type K 2 there is a maximum of one object of type K 1 . Example: "Mother has children."
- **N:N relationship** : Any number of objects of type K 2 are assigned to each object of type K 1 and vice versa. Example: "Order includes product."

### 6.1.4 Reflexive associations

A reflexive association occurs when multiple objects of the same class are related to each other.

## 6.2 Aggregation and composition

If an association end needs to be highlighted to indicate that it is a part-whole relationship, UML offers aggregation and composition as special associations. An open diamond on the aggregate side indicates an aggregation, while a filled diamond represents a composition. The objects involved in a part-whole relationship always form an acyclic graph.

- **Aggregation** : The semantics of a weak part-whole relationship consist solely in the fact that the aggregate can, logically, assume certain tasks as a representative for its parts, e.g., a department for all its employees. Fundamentally, the distinction between association and aggregation is difficult.  不是强跟随 不会跟着一起删除 
- **Composition** : The strong part-whole relationship is composition. In composition, a part can only belong to one aggregate at a given time. The part is copied or deleted together with the aggregate. Its existence depends on the aggregate. 跟着一起删除   This seems obvious for the example shown here of files as parts of a directory in the file system. If we delete a directory in the file system, for example, we also remove all the files in that directory. Even if we copy the directory to another location, we equally duplicate all the files in the directory. A file can only be in one directory at a time.

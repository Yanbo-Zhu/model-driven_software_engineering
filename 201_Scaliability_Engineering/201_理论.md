# 2 Scalability and elasticity 

Scalability describes to which degree a system can deal with more load when having access to more resources.
Elasticity describes what happens when adding resources.

## 2.1 Scalability – the ability to scale

Ideally, a system can serve twice the number of requests without changes in other QoS dimensions when doubling the amount of resources.
⇒ Describes the stable state before/after increasing resources and load
⇒ Describes an ability, i.e., whether a system supports auto-scaling doesn‘t matter*.

## 2.2 Elasticity – what happens when you actually do scale


Describes what happens while scaling.
⇒ Describes what happens in-between stable states.
⇒ Scaling time and scaling impact can be significant – especially when state needs to be migrated between machines

In an ideal* world, we would like to have linear scalability, i.e., the number of requests (or volume of load) a system is able to serve, grows linearly with the amount of resources it has access to. In practice, systems will often be able to offer linear scalability for a specific load/resource range but will run into limits for higher levels.
⇒ A component coordinating the overall system reaches its max load level (e.g., master server in GFS – see next slide)
⇒ The load balancer can no longer serve all requests directly, i.e., we need a load balancer in front of a group of load balancers instead
(= system gets slower due to extra-hop)
